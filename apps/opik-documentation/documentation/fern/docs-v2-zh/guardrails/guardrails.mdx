一个**防护（guard）**是一个已配置的检查。本页介绍 Opik 提供的五种防护类型：各自检测什么、你在其上配置什么，以及运行它需要什么。

你在 Opik UI 中把防护放入一个[策略](/guardrails/policies)，你的应用按名称运行该策略。配置存放在 Opik 中；你的代码只调用 `validate`。

## 快速开始

在 UI 中创建带有你所需防护的策略，然后从中构建一个护栏并验证你的文本。失败的检查会抛出异常，因此受保护的路径只有在 `validate` 返回后才会继续。

```python
from opik.guardrails import Guardrail
from opik import exceptions

guardrail = Guardrail.from_stored_policies(names=["no-financial-advice"])

llm_response = "You should buy some NVIDIA stocks!"

try:
    guardrail.validate(llm_response)
except exceptions.GuardrailValidationFailed as e:
    print(e)
```

该调用是阻塞的，因为重点正是在你的应用返回一个你不希望用户看到的响应之前停止它。

<Tip>
  参见[策略](/guardrails/policies)，了解如何创建策略、组合多个策略，以及在工作区中的每个应用上强制执行一个策略。
</Tip>

<Note>
  如果你自托管 Opik，PII、主题、提示注入和自定义分类器防护需要护栏服务器运行。使用 `./opik.sh --guardrails` 将其与其余栈一起启动，并参见
  [护栏服务器](/guardrails/server)页面了解 GPU 和部署选项。LLM 评判防护不需要它。
</Note>

## 五种防护类型

像 OpenAI 或 Anthropic 这样的提供商已经阻止了最普遍的风险，如有害或恶意内容。Opik 的防护覆盖的是残余风险，这些风险往往是你的产品特有的，需要更详细的配置。

每种防护都选择能为其问题提供准确性、延迟和成本最佳平衡的方法——传统 NLP 用于个人数据，小型语言模型用于主题和注入检测，完整的 LLM 用于细致的判断。

五种防护的配置方式相同：在策略中打开该防护，并填写它的字段。

### PII

检测敏感的个人信息，如姓名、地址、电子邮件地址、电话号码和信用卡详情。

**你配置什么**

- **要阻止的个人数据** — 要查找哪些类别。UI 提供最常出现的类别；底层检测器支持一个[长得多的列表](https://microsoft.github.io/presidio/supported_entities/)。
- **阈值** — 达到或超过该置信度即算作检测到。越低越严格。

_这里使用的方法利用传统 NLP 模型进行分词和命名实体识别。_

### 主题

让输入和输出保持在主题范围内。

**你配置什么**

- **受限主题** — 文本不得匹配其中任何一项。
- **允许主题** — 文本必须匹配其中至少一项。
- **阈值** — 达到或超过该分数即算作检测到主题。

你可以设置任意一个列表，或两者都设置。受限主题是常见情况：指定你的应用必须远离什么。

_此护栏依赖一个小型语言模型，具体来说是一个零样本分类器。_

### 提示注入

检测让你的 LLM 忽略、覆盖或泄露其指令的尝试，以及其他恶意查询。在用户输入上使用它，在越狱和注入攻击到达你的模型之前阻止它们。

**你配置什么**

- **阈值** — 达到或超过该注入概率即算作防护失败。越低越严格。

模型是固定的：此防护运行 [Opik Guard](/guardrails/prompt-injection-model)，一个我们为此任务训练的分类器。在自托管部署中，服务器需要一个 Hugging Face token 来获取它——参见[服务器配置](/guardrails/server#configuration)。

_此护栏依赖一个为提示注入检测而微调的小型语言模型。_

### LLM 评判

根据你用平实语言描述的规则检查文本。因为由一个完整的 LLM 来做评判，它能捕捉到启发式和分类器会遗漏的细微问题——给出受监管的建议、偏离你的品牌语气。

**你配置什么**

- **指令（Instructions）** — 规则，用你自己的话。例如："该文本不得提供医疗建议、诊断或剂量推荐。"
- **模型** — 由哪个模型评判。它必须可通过在 [AI Providers](/administration/workspace-settings/ai_providers) 下配置的 LLM 提供商获得。

<Note>
  评判是内联运行的，会为它所防护的每次调用增加延迟，因此优先选择你的提供商最新一代中快速、小型的模型，而不是大型推理模型。好的选择是低延迟档位，如 OpenAI
  `gpt-4o-mini`、Google Gemini Flash 模型或 Anthropic Claude Haiku 模型。
</Note>

这是唯一不使用护栏服务器的防护。它的模型调用作为护栏 span 下的一个嵌套 LLM span 记录，因此你可以在 trace 中检查确切的提示词、响应和 token 用量。

_此护栏依赖一个大型语言模型，最适合准确性比延迟更重要的复杂检查。_

### 自定义分类器

运行一个[你自己微调的模型](/guardrails/custom-guardrails)——一个回答你产品特有的某个是非问题的检查，例如回复是否偏离品牌。Opik 在你的标注示例上训练它并服务它，因此无需部署任何东西。

**你配置什么**

- **模型** — 运行你的哪个模型。只有就绪的模型才可选择。
- **阈值** — 达到或超过该分数即算作防护失败。

参见[自定义模型](/guardrails/custom-guardrails)了解如何微调一个。

_此护栏依赖一个在你自己的标注示例上微调的小型语言模型。_

## 处理失败

失败的护栏会抛出异常，你的应用代码需要处理它——重试、回退到安全的默认值，或返回错误，视情况而定。

<Warning>
  护栏是 fail-closed 的。如果某项检查无法评估（例如护栏服务器不可达、
  请求超时，或 LLM 评判提供商调用失败），`validate` 会抛出 `opik.exceptions.GuardrailValidationError`
  而不是让文本通过。该异常是 `GuardrailValidationFailed` 的子类，因此现有的
  `except GuardrailValidationFailed` 块也会停止请求。请组织你的代码，使受保护的路径只在
  `validate` 成功返回时才继续。
</Warning>

### 流式响应和长输入

反复调用 `guardrail.validate` 来逐块检查响应，或分别检查长输入的各部分。结果会作为额外的 span 添加到同一个 trace 上。

```python
for chunk in response:
    try:
        guardrail.validate(chunk)
    except exceptions.GuardrailValidationFailed as e:
        print(e)
```

## 处理结果

当护栏在 LLM 调用上失败时，Opik 会自动将信息添加到 trace 中。你可以把项目中的 trace 过滤到那些未通过护栏的。

## 性能和限制

如果 GPU 可用，护栏后端会自动使用它。对于生产使用，强烈建议在 GPU 节点上运行它。

当前限制：

- 主题护栏：最大输入大小为 1024 个 token
- 主题和 PII 护栏都支持英语

## 在代码中定义防护

防护也可以内联列出，而不是存储在策略中。这对于快速实验或只有一个脚本关心的检查很方便。

<Warning>
  以这种方式定义的防护对其他人不可见，只能通过编辑和重新部署你的应用来更改。对于任何在生产中运行的内容，请优先使用[策略](/guardrails/policies)。
</Warning>

```python
from opik.guardrails import Guardrail, PII, Topic
from opik import exceptions

guardrail = Guardrail(
    guards=[
        Topic(restricted_topics=["finance", "health"], threshold=0.9),
        PII(blocked_entities=["CREDIT_CARD", "PERSON"]),
    ]
)

try:
    guardrail.validate("You should buy some NVIDIA stocks!")
except exceptions.GuardrailValidationFailed as e:
    print(e)
```

每种防护类型都有一个对应的类，接受与 UI 暴露的相同设置：

| 防护 | 类 | 参数 |
| --- | --- | --- |
| PII | `PII` | `blocked_entities`、`threshold`、`language` |
| 主题 | `Topic` | `restricted_topics`、`allowed_topics`、`threshold` |
| 提示注入 | `PromptInjection` | `threshold` |
| LLM 评判 | `LLMJudge` | `name`、`instructions`、`model` |
| 自定义分类器 | `CustomGuardrail` | `model_name`、`threshold` |

## 手动护栏

对于五种防护类型都不适合的检查——一次性的启发式，或确实只是代码的业务规则——你可以自己运行它，并把结果直接记录到 Opik。不涉及任何防护类和护栏服务器。

<Tip>
  这与[自定义模型](/guardrails/custom-guardrails)不同，后者由 Opik 为你微调和服务。
  对于一次性启发式使用手动护栏；一旦同样的检查需要在高流量下快速、一致地运行，就微调一个模型。
</Tip>

<AccordionGroup>
  <Accordion title="示例：阻止竞争对手提及">
    ```python
    import opik
    import opik.opik_context
    import traceback

    # Brand mention detection
    competitor_brands = [
        "OpenAI",
        "Anthropic",
        "Google AI",
        "Microsoft Copilot",
        "Amazon Bedrock",
        "Hugging Face",
        "Mistral AI",
        "Meta AI",
    ]

    opik_client = opik.Opik()


    def check_competitor_mentions(generation: str, trace_id: str) -> str:
        # Start the guardrail span first so the duration is accurately captured
        guardrail_span = opik_client.span(name="Guardrail", input={"generation": generation}, type="guardrail", trace_id=trace_id)

        # Manual guardrail logic - detect competitor brand mentions
        found_brands = []
        for brand in competitor_brands:
            if brand.lower() in generation.lower():
                found_brands.append(brand)

        # The key `guardrail_result` is required by Opik guardrails and must be either "passed" or "failed"
        if found_brands:
            guardrail_result = "failed"
            output = {"guardrail_result": guardrail_result, "found_brands": found_brands}
        else:
            guardrail_result = "passed"
            output = {"guardrail_result": guardrail_result}

        # Log the spans
        guardrail_span.end(output=output)

        # Upload the guardrail data for project-level metrics
        guardrail_data = {
            "project_name": opik_client._project_name,
            "entity_id": trace_id,
            "secondary_id": guardrail_span.id,
            "name": "TOPIC", # Supports either "TOPIC" or "PII"
            "result": guardrail_result,
            "config": {"blocked_brands": competitor_brands},
            "details": output,
        }
        try:
            opik_client.rest_client.guardrails.create_guardrails(guardrails=[guardrail_data])
        except Exception as e:
            traceback.print_exc()

        return generation


    @opik.track
    def main():
        good_generation = "You should use our AI platform for your machine learning projects!"
        check_competitor_mentions(good_generation, opik.opik_context.get_current_trace_data().id)

        bad_generation = "You might want to try OpenAI or Google AI for your project instead."
        check_competitor_mentions(bad_generation, opik.opik_context.get_current_trace_data().id)


    if __name__ == "__main__":
        main()
    ```
  </Accordion>
</AccordionGroup>
