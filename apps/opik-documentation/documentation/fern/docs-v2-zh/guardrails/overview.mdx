护栏是与你的 LLM 调用内联运行的实时检查，用于在不安全的输入和输出到达用户之前捕获它们。与离线测试不同，护栏在生产环境中针对实时流量运行，充当应用周围的安全层。

## Opik 提供什么

- **五种防护类型** — PII 检测、允许和受限主题、提示注入和越狱检测、用平实语言编写的 LLM-as-a-judge 检查，以及你自己训练的分类器。
- **存储的策略** — 在 Opik UI 中定义一次你的检查，并从应用中以名称引用它们。工作区范围的策略也可以在每个应用上强制执行，无论它是否请求。
- **模型微调** — 对于内置防护未覆盖的检查，可以在你自己的标注示例上微调一个语言模型。Opik 托管训练、报告结果有多准确，并内联服务该模型。无需你自己的训练基础设施，也无需部署步骤。
- **完整可观测性** — 每一次护栏运行都作为 span 记录在它所保护的 trace 上，因此你可以检查什么失败了，并跟踪随时间的失败率。

## 概念

这些页面中反复出现三个词，提前区分它们会很有帮助。

| 术语 | 含义 |
| --- | --- |
| **防护（Guard）** | 一个已配置的检查——例如"阻止信用卡号"。每个防护都有一个类型：PII、主题、提示注入、LLM 评判或自定义分类器。 |
| **策略（Policy）** | 存储在你的工作区中的一组命名的防护。你的应用引用该名称，因此检查可以改变而无需改代码。 |
| **护栏（Guardrail）** | 你的应用实际调用的东西。你从一个或多个策略构建它，它会对你交给它的每一段文本运行这些策略所持有的每个防护。 |

简而言之：策略是配置，护栏是执行。一个护栏可以组合多个策略，一个策略可以被任意数量的应用使用。

## 为什么护栏重要

LLM 是非确定性的。同一个提示词可能产生不同的响应，而且再多的预生产测试也无法保证生产中的每个响应都是安全的。护栏通过在每一个请求发生时强制执行你的要求来填补这一差距。

护栏帮助你控制的常见风险：

- **敏感数据泄露** — 个人身份信息（PII），如姓名、地址或信用卡号出现在输入或输出中。
- **偏离主题的响应** — 模型回答了超出你应用范围的问题。
- **有害或不合规的内容** — 违反你的策略或监管要求的输出。
- **业务特定风险** — 竞争对手提及、不允许的主张，或任何你所在领域独有的规则。

因为护栏在响应返回之前运行，它让你可以阻止一个糟糕的响应、重试，或回退到安全的默认值，而不是把问题暴露给你的用户。

## 护栏 vs. 在线评估

Opik 为你提供了两种检查生产流量的互补方式。它们解决不同的问题，大多数团队两者都用。

关键区别是**阻塞与非阻塞**：护栏内联运行，可以阻止响应被返回；而在线评估对已经记录的 trace 异步运行。

| | 护栏 | 在线评估 |
| --- | --- | --- |
| **执行** | 内联、同步 | 异步，在 trace 记录之后 |
| **对响应的影响** | 阻塞——可以停止或改变响应 | 非阻塞——绝不影响响应 |
| **主要目标** | 实时阻止不安全的输入和输出 | 监控质量并大规模检测问题 |
| **覆盖范围** | 每个请求 | 可配置的采样率 |
| **延迟影响** | 给每次调用增加延迟 | 无 |
| **典型检查** | PII、受限主题、自定义业务规则 | 幻觉、答案相关性、内容审核、自定义 LLM-as-a-Judge 指标 |

当失败的检查必须改变用户看到的内容时使用**护栏**——例如，阻止泄露 PII 或偏离主题的响应。这个检查值得增加延迟，因为让该响应通过的成本很高。

当你想在不增加延迟的情况下了解你的应用在生产流量中的行为时，使用**[在线评估](/production/online-evaluation/rules)**。它对已记录的 trace 运行 LLM-as-a-Judge 指标，按你选择的任何速率采样，并展示趋势，以便你随时间识别问题。

<Tip>
  两者配合得很好：使用在线评估来发现对你的应用重要的失败模式，然后添加护栏来阻止那些绝不允许到达用户的模式。
</Tip>
