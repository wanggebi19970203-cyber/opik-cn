找到节省是分析；保持节省是策略。成本策略把在仪表板中做出的决定——默认模型、思考预算、输出上限、被拒绝的 MCP 服务器和技能——转化为每台开发者机器上的托管设置，并使其保持在那里。

本页是策略行为的完整图景：组织策略和用户策略如何配合、谁能改什么、变更如何到达设备，以及当开发者在本地编辑某个托管设置或你在仪表板中清除它时，究竟会发生什么。

<Note>
  一旦设备上安装了 Cost Intelligence，策略就会到达该设备。如果你还没有推广，请从[安装](/cost-intelligence/install/overview)开始。
</Note>

## 设定组织基线

**组织策略**是全团队基线：除非你为某个开发者单独决定，否则每个开发者都处于这些值上。你可以通过应用 **Cost Savings** 页面上的建议来创建一条——每一条都根据你的流量定价，应用它即将其写成策略——或者直接在 **Organization Policies** 下设置一个值。

<Frame>
  <img src="/img/v2/cost-intelligence/org_policies.png" alt="组织策略，包含一个锁定的默认模型和一个未锁定的推理 effort 设置" />
</Frame>

一旦设置完成，交付是自动的。引导配置（工作区、API 密钥、基础 URL）通过[托管设置](/cost-intelligence/install/managed-settings)或 [MDM](/cost-intelligence/install/mdm)一次性交付；此后成本策略无需任何额外推送。你只需部署一次，之后即可从仪表板管理支出。

## 为每个用户授予例外

基线只有在例外很容易授予时才站得住脚。**用户策略**是叠加在组织基线之上的每用户值，因此某个需要更大思考预算的团队绝不会意味着为所有人放宽它。管理员可以为任何开发者设置，开发者在被允许的情况下也可以从他们的 **My preferences** 页面设置自己的值。

解析规则很简短：

- **每用户值覆盖组织值**，仅对该用户生效。没有覆盖的每个人都停留在基线上。
- **每个设置都带有锁。** 锁定的意思是开发者无法自己更改该设置；管理员仍然可以。未锁定意味着开发者可以从 **My preferences** 设置自己的值。
- **自定义的值会被标注**——由用户自定义，或由管理员自定义——这样你就能看到哪些设置带有覆盖。没有标注的设置处于组织基线上。
- **覆盖可回退。** 移除每用户值会让开发者直接回到组织基线。

<Frame>
  <img src="/img/v2/cost-intelligence/user_policy_drawer.png" alt="一个用户的策略抽屉，展示管理员对组织模型的覆盖，以及一个仍继承组织值的设置" />
</Frame>

推演一遍：假设组织默认模型被锁定，组织思考预算已设置但保持未锁定。每个开发者都运行在该模型上且无法更改它。大多数人也运行在组织思考预算上，但需要更多的开发者获得每用户覆盖——并且之后仍可自行调整它，因为该设置未锁定。回退他们的覆盖会让他们回到组织预算。

<Tip>
  把组织基线设得比你认为需要的更紧，再按用户授予例外。这比一条你一直想收紧却收不紧的宽松基线要好管理得多，而且例外列表本身就变成了关于谁需要什么的有用数据。
</Tip>

## 如何识别开发者

Cost Intelligence 通过登录到编码智能体的账户邮箱来识别开发者——对于 Claude Code，就是从其登录状态观察到的 Anthropic 账户邮箱。没有单独的登录，开发者无需输入任何东西。每用户策略和支出仪表板都以同一邮箱为键，因此你授予例外的开发者，就是你在排行榜上查看其支出的同一个人。如果某人以一个你不认识的邮箱出现——个人 Anthropic 账户，或不存在任何账户配置文件的网关设置——请通过 `OPIK_CIPX_USER_EMAIL` 固定其身份，该变量可通过[托管设置](/cost-intelligence/install/managed-settings)或 [MDM](/cost-intelligence/install/mdm)下发。

## 变更如何到达设备

没有推送，也没有需要重启的东西。每台设备都会获取其已登录开发者的生效策略并自行应用，一遍又一遍——因此偏离策略的机器会被自动拉回，无需你做任何事。当你保存变更时，确认信息说它大约 5 分钟后生效，实际情况正是如此：

- **活动设备大约每 5 分钟检查一次。** 活动是指过去 30 分钟内有任何智能体请求。空闲机器会停止检查，并在开发者再次开始工作后片刻补上——一台在变更期间休眠的笔记本电脑，会在其主人发起第一次请求后的片刻内回到策略上。
- **某些设置从下一个会话开始生效。** Claude Code 只在会话开始时读取少数几个设置——最明显的是模型——因此变更（或清除）会在开发者开始下一个会话时变得可见。
- **它在各处行为一致。** Claude Code 和 Codex 都是如此，无论是插件安装还是 macOS 应用。

## 当开发者在本地更改设置时

开发者可以通过两种方式更改托管设置，二者的结局不同。

<Frame>
  <img src="/img/v2/cost-intelligence/my_preferences.png" alt="开发者的 My preferences 页面，包含一个无法更改的锁定设置和一个可以更改的未锁定设置" />
</Frame>

通过产品：如果设置未锁定，开发者从 **My preferences** 设置自己的值。这会创建一个每用户值——与作为管理员的你设置的是同一种——在仪表板中显示为由用户自定义，并且像任何其他覆盖一样可回退。

手动编辑：直接编辑 `~/.claude/settings.json` 中的托管值不会保持。只要策略处于设置状态，它的值就会在每次检查时重新应用，因此手动编辑会在几分钟内被纠正，而不是等到未来的某次推广。锁控制的是开发者在产品中能做什么，而不是文件——无论哪种情况，文件都会保持为解析后的策略值。

<Note>
  **策略是默认值，而非硬性强制。** 它们被应用到 Claude Code 读取的用户设置上，而 Claude Code 会让更高优先级的设置覆盖这些设置——项目自己的 `.claude/settings.json`，或会话开始时传入的设置文件。在那里设置值的开发者会覆盖该策略对那个项目或会话的约束；Cost Intelligence 管理用户设置，不触及那些层级。对大多数团队来说，一个可见的基线已经足够；如果你需要开发者完全无法覆盖的值，那是一个超出这些策略的设备管理问题。
</Note>

## 当你清除某个设置时

在仪表板中清除设置会以保守的方式将其从设备移除：设备只有在它仍持有策略所应用的确切值时才会删除该键。其他任何情况都会被保留，因此清除策略绝不会破坏策略没有写入的值。下一会话规则在这里同样适用——清除组织模型后，每个开发者会从他们的下一个会话起回到智能体自己的默认值。

### 行为速览

| 你这样做 | 在设备上 | 何时 |
| --- | --- | --- |
| 设置或更改策略值 | 写入托管键 | 活动状态下约 5 分钟内；模型类设置从下一个会话起 |
| 锁定一个设置 | 开发者无法再在产品中更改它 | 立即在仪表板中生效 |
| 开发者手动编辑托管值 | 策略值被重新断言，覆盖该编辑 | 在下一次检查时 |
| 开发者在 My preferences 中设置未锁定值 | 成为每用户覆盖，像任何策略值一样应用 | 活动状态下约 5 分钟内 |
| 清除一个策略值 | 若该键仍持有策略值则移除；不同的值会被保留 | 约 5 分钟内；模型类设置从下一个会话起 |

## 策略同步在设备上触及什么

写入面被刻意收窄，并且在每一种安装方式中都相同：

| | |
| --- | --- |
| **它写什么** | 只写 `~/.claude/settings.json` 和 `~/.codex/config.toml` 中的托管策略键——每个文件的其余部分属于开发者自己 |
| **何时不写** | 无法解析的设置文件会被原样保留，而不是修复 |
| **失败时** | 失败只会出现在本地日志和错误遥测中 |

如需了解 Cost Intelligence 读取和上报的更广泛图景，参见[数据、隐私和安全](/cost-intelligence/data-privacy-security)。

## 值得了解的边界

过旧的 Claude Code 构建会被置于未管理状态；它们会在更新后接上策略。

<Warning>
  卸载 Cost Intelligence 会保留最后应用的值——它不会在离开时撤销自己的工作。如果你正在退役设备，请先从仪表板清除你的策略，让设备回到智能体默认值，然后再卸载。
</Warning>
