一旦你的智能体开始处理真实流量，靠浏览追踪来发现反复出现的故障就无法扩展了。诊断会按计划扫描你项目的追踪，将重复出现的故障归入同一个问题，并呈现根本原因、建议的修复方案以及证明它的追踪，这样你就能在用户报告之前发现问题。

## 工作原理

诊断由 Ollie 驱动，因此它不依赖固定的规则或阈值。它会像你一样读取完整的追踪，寻找诸如工具调用循环、格式错误的 API 调用、幻觉输出或延迟回归等模式。

- **每日扫描：** 一旦启用，Opik 会每天在 UTC 时间 00:05 自动扫描每个项目最近 24 小时的追踪。
- **按需扫描：** 随时点击**运行诊断**，立即分析最近 24 小时的数据，而无需等待每日计划。
- **去重的问题：** 跨追踪匹配到的故障会被归入同一个问题，而不是逐一报告，因此一个在 40 条追踪中都出现的 bug 仍然只需要一次修复。

<Note>
  诊断需要为你的工作区启用 Ollie AI 助手。扫描会消耗你的 Ollie Token，请参阅设置对话框了解计费详情。
</Note>

## 开启诊断

当你第一次打开某个项目的**诊断**页面时，系统会提示你开启它。一旦启用，一次扫描会立即启动，然后每天自动运行。

## 查看问题

列表中的每个问题都会显示其严重程度（`critical`、`high`、`medium` 或 `low`）、已发生的次数以及上次出现的时间，这样你就可以在打开任何单个问题之前进行排序和确定优先级。

打开一个问题会显示：

- **首次出现 / 上次出现**和**发生次数**（总次数以及最新一次扫描中的次数）
- **受影响的用户**
- **摘要：** Ollie 用平实语言描述的发现
- **Ollie 修复方案：** 可能的根本原因和一条建议的修复方案，并带有一个**继续使用 Ollie** 按钮，可转交给 Ollie 聊天侧边栏以进一步深入，或直接应用代码修复
- **随时间变化的发生次数：** 一张图表，展示该问题自首次被检测到以来的触发频率
- **受影响的追踪样本：** 几条展示该问题的追踪，直接链接到追踪视图

## 解决问题

修复了根本问题后，点击问题上的**解决**。已解决的问题会移到**已解决的问题**页面，如果该模式再次出现，你可以随时重新打开它们。

## 设置

使用**运行诊断**旁边的设置图标来打开或关闭每日自动扫描。这不会影响按需扫描：即使自动扫描已暂停，你仍然可以手动点击**运行诊断**。
