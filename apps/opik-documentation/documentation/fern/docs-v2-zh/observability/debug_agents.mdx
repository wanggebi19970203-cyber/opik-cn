你的智能体返回了错误的答案、忽略了你提供给它的上下文，或者耗时是应有时间的两倍。追踪就在 Opik 中——但仅靠追踪并不能告诉你它*为什么*发生，或者该如何修复。这正是 [Ollie](/ollie) 的用武之地。

## Ollie 可以访问什么

Ollie 不仅仅是一个聊天机器人——它拥有可以作用于你的工作区和代码的工具。

- **读取和分析追踪** — Ollie 读取完整的跨度树，包括输入、输出、延迟、Token 数量和反馈评分。它可以深入单个跨度、并排比较追踪，并在你的项目中搜索模式。
- **搜索你的工作区** — 追踪、线程、数据集、实验和提示词都可以被查询。Ollie 可以聚合数据、找出异常值，并呈现出你原本需要手动查询才能发现的趋势。
- **读取和编辑你的代码** — 当你使用 [`opik connect`](/development/agent-playground) 连接你的仓库后，Ollie 会获得对你的源文件的只读访问权限。它可以提出编辑建议，由你审查并在磁盘上发生任何变化之前批准。
- **运行你的智能体** — 在 `opik connect` 激活的情况下，Ollie 可以使用失败追踪中的输入重新运行你的智能体，以实时验证修复。新的追踪会自动流式传回 Opik。
- **管理测试套件** — Ollie 可以将追踪作为测试用例添加到测试套件中，定义断言，触发评估运行，并汇总通过/失败结果。
- **导航 Opik UI** — Ollie 可以直接链接到它在对话中引用的追踪、实验、数据集和提示词。

<Note>
  代码访问和智能体执行需要 [`opik connect`](/development/agent-playground) 在你的项目目录中运行。没有它，Ollie 仍然可以分析追踪和搜索你的工作区，但无法读取你的源文件或重新运行你的智能体。
</Note>

## 调试-修复-验证循环

提升智能体质量的最快方式是形成一个紧密的循环：找到一条糟糕的追踪，理解它，修复它，并确保它保持修复状态。Ollie 端到端地处理这一切。

<Steps>
  <Step title="找到一条失败的追踪">
    从 Opik 仪表板开始。按错误状态、较低的反馈评分或延迟尖峰来过滤追踪，以找到一次表现不符合预期的运行。
  </Step>
  <Step title="询问 Ollie 哪里出了问题">
    从追踪视图打开 Ollie，描述看起来不对劲的地方。Ollie 会读取完整的跨度树——每一次 LLM 调用、工具调用和检索步骤——并识别出根本原因。

    <Frame>
      <img src="/img/v2/ollie/step-2-ask-ollie.png" alt="Ollie 分析一条追踪并识别根本原因" />
    </Frame>
  </Step>
  <Step title="让 Ollie 修复你的代码">
    一旦 Ollie 知道 bug 在哪里，它会通过 `opik connect` 读取相关的源文件并提出修改建议。你会看到 diff 并批准它——没有你的点击，什么都不会发生。

    <Frame>
      <img src="/img/v2/ollie/step-4-suggested-fix.png" alt="Ollie 通过 diff 视图提出代码修复建议" />
    </Frame>
  </Step>
  <Step title="用测试套件验证">
    让 Ollie 将原始追踪添加为回归测试用例，然后针对更新后的智能体运行该套件。你会得到通过/失败摘要，以及一个在 bug 再次出现时能捕获它的测试。

    <Frame>
      <img src="/img/v2/ollie/step-6-eval-verification.png" alt="Ollie 运行测试套件并展示通过/失败结果" />
    </Frame>
  </Step>
</Steps>

每一次循环都会让你的智能体更加健壮。随着时间推移，你的测试套件会成为一个直接从真实失败中构建起来的全面回归防线。

## 示例提示词

当你用平实的语言描述问题时，Ollie 的效果最好。以下是一些常见调试场景的提示词：

### 调查失败

- *"为什么最终答案忽略了检索到的上下文？"*
- *"这条追踪中哪个跨度导致了延迟尖峰？"*
- *"工具调用返回了空结果——哪里出了问题？"*

### 比较追踪

- *"将这条失败的追踪与同一查询最近一次成功的追踪进行比较"*
- *"找出本周所有工具调用超时的追踪"*
- *"上一次成功运行和这次失败之间发生了什么变化？"*

### 构建测试覆盖

- *"将这条追踪添加到我的 customer-support-qa 套件中，断言要求：响应必须引用所提供上下文中的具体步骤"*
- *"针对更新后的提示词运行 customer-support-qa 套件"*
- *"为什么这次运行中 5 个测试项里有 3 个失败了？"*

### 了解你的工作区

- *"显示上一次实验的数据集"*
- *"过去一周这个项目中追踪的平均延迟是多少？"*
- *"哪些提示词被最多的实验使用？"*
