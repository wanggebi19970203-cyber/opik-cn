`opik migrate` 会将一个实体——以及附加到它上面的所有内容——**在同一个工作区内**从一个项目移动到另一个项目。它会将实体的完整版本历史及其相关数据复制到目标项目中。

它有两个子命令：

- **`opik migrate dataset`** — 一个数据集（或测试套件）及其完整版本历史，外加附加到它上面的实验、追踪、跨度、反馈评分、断言结果、评论和优化。
- **`opik migrate prompt`** — 一个提示词及其完整版本历史。

用它来将一个实体及其历史整合或重新安置到另一个项目下。

<Note>
  这些命令会在**单个工作区内的项目之间**移动数据。要在不同的 Opik 安装或环境之间移动数据，请改用 [`opik export` / `opik import`](/tracing/advanced/export-data#command-line-tools)。
</Note>

<Warning>
  迁移会**将源重命名**为 `<name>_v1`，并将原始名称赋予目标。请先用 `--dry-run` 预览，以确切了解将会发生什么变化。
</Warning>

## 选项

`--workspace` 和 `--api-key` 标志放在 `opik migrate` 组上，位于子命令**之前**。其余选项由 `dataset` 和 `prompt` 共用。

| 标志                       | 默认值                                          | 描述                                                                                             |
| -------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `NAME`（参数）             | —                                               | 要迁移的源数据集或提示词的准确名称。                                                             |
| `--to-project`             | —（**必填**）                                   | 目标项目。它必须已经存在——如有需要请先创建。                                                    |
| `--from-project`           | 整个工作区                                      | 用于提示源实体所在项目的可选提示。省略则以搜索整个工作区。                                      |
| `--dry-run`                | `false`                                         | 在不做任何更改的情况下预览将会发生什么。参见[预览迁移](#预览迁移)。                              |
| `--workspace`（组标志）    | `OPIK_WORKSPACE` → `~/.opik.config` → `default` | 要操作的工作区。                                                                                 |
| `--api-key`（组标志）      | `OPIK_API_KEY` → `~/.opik.config`               | Opik API key。                                                                                    |

## 预览迁移

为任何迁移添加 `--dry-run`，即可**在不更改任何内容**的情况下确切了解它会做什么——不会重命名任何内容，也不会复制任何内容。该命令会解析源实体，打印它将逐步执行的计划，然后退出。

```bash
opik migrate dataset "MyDataset" --to-project="production" --dry-run
```

使用预览来确认源解析到了正确的实体，并且目标项目正确无误。当计划看起来正确时，再次运行相同的命令（不带 `--dry-run`）来应用它。

## `opik migrate dataset`

```bash
opik migrate dataset NAME --to-project=DESTINATION_PROJECT [OPTIONS]
```

`NAME` 是源数据集的准确名称。普通数据集和测试套件都受支持。在应用之前，请先[使用 `--dry-run` 预览](#预览迁移)。

### 会复制什么

| 实体                | 会带过去的内容                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------- |
| **数据集**          | 名称、描述、可见性、标签以及类型（数据集或测试套件）。                                            |
| **版本历史**        | 每个版本，按顺序排列，其项目内容和顺序与源一致。                                                  |
| **项目（Items）**   | 每个项目的数据、描述、标签、评估器、执行策略和来源。                                              |
| **实验**            | 名称、类型、评估方法、标签和元数据。                                                              |
| **追踪**            | 输入、输出、元数据、标签、时间信息、线程、错误和环境。                                            |
| **跨度**            | 完整的跨度树、输入和输出、元数据、模型、提供商、使用量、成本、标签和错误。                        |
| **反馈评分**        | 追踪和跨度上的反馈评分。                                                                          |
| **断言结果**        | 针对测试套件。                                                                                    |
| **评论**            | 追踪和跨度上的评论。                                                                              |
| **优化**            | 链接到数据集的优化，其实验会在目标上重新关联。                                                    |

### 运行时会发生什么

`--dry-run` 计划中会出现相同的步骤：

| #   | 步骤                 | 它的作用                                                         |
| --- | -------------------- | ---------------------------------------------------------------- |
| 1   | 重命名源             | 将源重命名为 `<name>_v1` 以释放其名称。                          |
| 2   | 创建目标             | 在 `--to-project` 下以原始名称创建数据集。                       |
| 3   | 回放版本             | 按顺序将每个版本回放到目标上。                                   |
| 4   | 复制优化             | 重新创建任何链接到该数据集的优化。                               |
| 5   | 复制实验             | 重新创建实验，连同它们的追踪和跨度。                             |

### 不会复制什么

- **实验上的提示词快照** — 请使用 `opik migrate prompt` 单独迁移提示词。
- **追踪和跨度上的附件** — 图像和音频等文件不会被复制。
- **线程标签、状态、反馈评分和评论** — 追踪本身（包括它们的环境）确实会带过去，但这些线程级别的字段目前还不会。

### 示例

```bash
# 迁移一个数据集（连同它的实验、追踪和跨度）
opik migrate dataset "MyDataset" --to-project="production"

# 在不做任何更改的情况下预览
opik migrate dataset "MyDataset" --to-project="production" --dry-run

# 告诉它源实体位于哪个项目
opik migrate dataset "MyDataset" --to-project="production" --from-project="staging"
```

### 恢复被中断的迁移

如果迁移被中断——崩溃、连接断开，或者进程被终止（例如，在非常大的数据集上内存耗尽）——只需在同一台机器上重新运行完全相同的命令。它会从断点继续，而不是从头开始：

- **已迁移的实验会被跳过。** 每个实验完成后都会保存检查点，因此重新运行会从最后一个完成的实验继续。进度条会反映这一点——一个已完成约 53% 的迁移会从接近 53% 处继续，而不是 0%。
- **在迁移中途被中断的实验会被干净地重新迁移。** 它在目标上的部分追踪、跨度和实验记录会先被删除，因此重新运行不会留下重复项。

检查点存储在本地 `~/.opik/migrate-checkpoints/` 下，以工作区 + 目标项目 + 数据集名称作为键，因此无论你从哪个目录运行，重新运行都能继续。迁移成功完成后，检查点会被自动移除。恢复仅限运行迁移的那台机器——换到另一台机器会重新开始。（实验是检查点的粒度；没有更细的按追踪或按跨度的恢复。）

## `opik migrate prompt`

```bash
opik migrate prompt NAME --to-project=DESTINATION_PROJECT [OPTIONS]
```

`NAME` 是源提示词的准确名称。此子命令仅迁移提示词及其版本历史——它不会复制实验、追踪或跨度。在应用之前，请先[使用 `--dry-run` 预览](#预览迁移)。

### 会复制什么

- **提示词** — 名称、描述、标签和模板结构。
- **版本历史** — 每个版本，从最旧的开始，包括其模板、元数据、类型、变更描述和标签。
- **提交哈希** — 每个版本的提交哈希都会被保留，因此历史记录与源完全一致。

它会将源重命名为 `<name>_v1`，在 `--to-project` 下创建目标提示词，并回放每个版本。

### 示例

```bash
# 迁移一个提示词及其完整版本历史
opik migrate prompt "MyPrompt" --to-project="production"

# 在不做任何更改的情况下预览
opik migrate prompt "MyPrompt" --to-project="production" --dry-run
```

## 故障排查

- **名称已被使用** — 重命名目标 `<name>_v1` 已经存在。请重命名或删除冲突的实体，然后重新运行：

  ```
  Cannot rename source to 'MyDataset_v1' — that name is already used by a dataset in project 'staging'. Rename or delete the conflicting dataset and re-run.
  ```
